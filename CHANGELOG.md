# Changelog

All notable changes to this project are documented here. The project follows [Semantic Versioning](https://semver.org). Versions below 1.0.0 are alpha and may include breaking changes.

## [0.1.0-alpha] - Unreleased

### Added

- Shared model from the operator's workspace. A workspace whose endpoint uses the server's shared model key, on a server with no `MYMORNINGNEWS_ANTHROPIC_API_KEY`, now runs on the model the operator connected and verified in the default workspace (an API key or an agent CLI sign-in such as a Claude Code setup token). Calls are logged and limited in the workspace that made them; setup checks report the shared model as ready, and client config reports the platform model as configured.
- `Models.AgentClisAdminsOnly` (`MYMORNINGNEWS_MODELS_AGENT_CLIS_ADMINS_ONLY`): when agent CLIs are allowed, only global administrators can connect them; everyone else sees them as unavailable. The hosted profiles now allow agent CLIs for administrators only (they had them off), so the operator can use a Claude Code setup token or a Codex `auth.json` on the hosted service.
- Published Docker images and build scripts. `build-all.sh <tag>` (and `.bat`) builds every image on the Docker cloud builder for `linux/amd64` and `linux/arm64` and pushes `jchristn77/mymorningnews-<type>:latest` and `:<tag>` for server, dashboard, mcp, searxng, tts, ollama, prometheus, tempo, loki, and grafana; `build-<type>.sh` builds one. `docker/compose.yaml` now uses those images and no build contexts; the Prometheus, Tempo, Loki, and Grafana configurations (with the Grafana dashboards) are part of their images. `docker/update.sh` runs `docker compose pull && docker compose down && docker compose up -d && docker ps -a`, and the factory reset pulls instead of building. `docker/production/` is a self-contained deployment for a host behind a load balancer (server on 8000, dashboard on 8080) with its own `update.sh`.
- Run and stage cost as first-class data. Every model call records the run stage it was made in (`llmcalls.runstageid`, through an async scope the pipeline opens per stage), and each stage stores its model calls, unpriced calls, input, output, cached, and reasoning tokens, and estimated cost when it finishes. Runs gained call, unpriced-call, cached-token, and reasoning-token counts, and their totals update after every stage instead of only at the end. `GET /v1.0/api/runs/{id}/costs` reports totals (input and output cost, cost per new finding), each stage with its share of the run's cost, each model, and each task role, computed live from the calls. `GET /v1.0/api/llm-calls?runStageId=` lists one stage's calls, and runs sort by `estimatedCostUsd` or `durationMs`. Migration 21 attributes older calls to stages by time. Agent CLIs signed in with an API key record the cost the CLI reports; subscription sign-ins and endpoints without prices count as unpriced rather than $0. The dashboard shows cost on every runs table, a cost header and per-stage cost with shares on the run page, a breakdown by model and task, and cost per run on the topic page.
- Workspace setup checks. `GET /v1.0/api/setup` reports what the workspace still needs: a chat model with a key that passed a live test call (required), a web search provider that answered a test query (required), and, for administrators, embeddings and email delivery (optional). `POST /v1.0/api/setup/model-key` stores a key encrypted in the vault (rotating the endpoint's own credential when it has one) and verifies it on the spot; `POST /v1.0/api/setup/verify` re-checks everything. The dashboard shows administrators a Setup page and everyone else a notice until every required check passes, and the mobile app shows the same notice. The hosted service's own key is checked once per server process instead of per tenant.
- Agent CLI model providers: Claude Code, Codex, Gemini CLI, and Mux, all already in the server image, can serve every chat task. Each endpoint picks how it signs in (`authMethod`): Claude Code with a `claude setup-token` subscription token, an Anthropic API key, or the sign-in already on the server; Codex with the `auth.json` from `codex login`, an OpenAI API key, or the server's sign-in; Gemini CLI with its Google sign-in file (`oauth_creds.json`), a Gemini API key, or the server's sign-in; Mux with its `endpoints.json`. Each CLI endpoint runs in a private home folder (`Models.CliHomeDirectory`, kept in the `clihome` volume) with the CLI's most restricted permission mode and an empty working folder; sign-in files are written only when the stored copy changes, so tokens the CLI refreshes are kept, and deleting the endpoint removes the folder. CLI endpoints answer structured requests in JSON (no tool calls, so agentic search falls back to planned queries). `Models.AllowAgentClis` turns them off; the hosted overlay does.
- Setup page choices: `GET /v1.0/api/setup/options` lists hosted APIs, agent CLIs (with whether each is installed and allowed), and self-hosted servers with their sign-in methods; `POST /v1.0/api/setup/connect` stores the chosen secret, points every chat task at the endpoint, and tests it with a live prompt. Pasted secrets are checked first (an API key pasted as a setup token, or an `auth.json` with no sign-in, is refused with a message saying what to do). Vault credentials gained the `SignInFile` kind.
- Model endpoints record `lastValidationSucceeded`: true after a successful validation or model call, false after a failed validation or a 401 or 403 from the provider, and cleared when the provider, URL, credential, or model changes or the key is rotated. Validation responses include `succeeded`.
- 409 `SetupRequired`: starting the topic wizard, its model steps, and one-time requests are refused with a message naming what to fix when the refinement endpoint has no key or failed its last check, instead of failing partway through the wizard.
- SDKs (C#, JavaScript, Python): a setup resource (`Setup.GetStatusAsync`, `VerifyAsync`, `SetModelKeyAsync`; `setup.status`, `verify`, `setModelKey`; `setup.status`, `verify`, `set_model_key`), typed `SetupRequiredException` / `SetupRequiredError` with the setup check key, `lastValidationSucceeded` on model endpoints, and `succeeded` on validation results, with harness cases. `REST_API.md` and the Postman collection document the three setup routes and the 409 `SetupRequired` responses.

### Changed

- Ranking: `Pipeline.RelevanceGateScore` (off by default) stops feedback, novelty, source, and recency from lifting a finding the model scored below it. Under the benchmark stub, 50 empties the off-topic briefing but hides three relevant pages on the live dataset; a paid round decides the default.
- Update detection without embeddings: a reworded follow-up that shares enough title and summary words with an earlier finding (`Pipeline.TextUpdateSimilarity`, default 0.35) is judged by the model as a duplicate, an update, or new.
- Client config reports whether the platform model key is configured, and the dashboard warns when an endpoint relies on a missing one. The preference line in emails says "from 1 rating".

- Free plan: $3 a month, 1 topic, daily schedules, 2 runs a day, 10 audio minutes. Complimentary: $10, 2 topics, daily, 4 runs, 30 audio minutes. Promotional codes last 30 days by default. Unedited stored values move to the new defaults at startup.
- The Unlimited plan no longer sets a schedule floor; the server's scheduler minimum applies.

  - Text longer than its database column (user names, model endpoint, feed token, topic, search provider, tenant, vault, voice, MCP server, role, and other names) is a 400 `ValidationFailed` naming the field and its limit instead of a 500, and topics and search providers no longer cut long names silently. A value too long for its column that gets past the checks is a 400 too (UT-004).
  - `docker/factory/reset.sh --keep-ollama` (and `reset.bat`) removes only the volumes of the compose project it resets, found by their compose labels, instead of every volume whose name starts with `mymorningnews_`; the script shows the project before asking to confirm (UT-006).
  - The Postman collection runs top to bottom on a fresh stack: every delete is in a Cleanup folder after the folders that use the records, logout and a restart (with the administration key) are in a Run last folder, Create a tenant saves `newTenantId` instead of overwriting `tenantId`, Change my password and Update server settings send back the current values, and list requests save the first item's ID for the reads that follow (UT-007).
  - A sign-up user with no model key gets a message they can act on (add a key under Models, or ask the operator) instead of "The platform model key is not configured on this server." (UT-011).
  - Run email times use the reader's profile time zone (then the topic owner's, the topic's schedule zone, the tenant's, or UTC) and show the zone, such as "12:51 PM HST" (UT-014).
  - README and MCP_API.md start the MCP profile with `--build` and explain that the image tags are shared by every compose project (UT-015).
  - The Python harness schedules its one-time request 30 days ahead instead of in 2099 (UT-016).
  - A run whose Fetch stage reads none of the selected pages, while search and the model work, ends Partially succeeded with the warning "Nothing new could be read" and sends no failure push; a run fails only when search or the model fails (UT-018).
  - Errors no longer show internal names: no "(Parameter 'apiKey')", structured output failures name what was asked for ("could not be used as a dimension proposal"), a value of the wrong JSON type names the field and what it takes (for an enum, the valid values) instead of `System.Nullable`1[...]`, and "Value cannot be null." names the missing value (UT-020).
  - A duplicate unique value names the record and field, such as "A model endpoint with that name already exists.", with the field in `details` (UT-021).
  - Adding a constraint a topic already has (same kind and value, ignoring case) returns the existing one; an update that would duplicate one is a 409. Blank names are refused, and a user name of only spaces is stored as unset (UT-023).
  - The README and the hosted web search message no longer list Azure OpenAI, which is not a model provider here (UT-024).
  - HOSTING.md gives the right health URL (`/v1.0/api/health`) and the verification link default (48 hours) (UT-025).
  - `sdk/README.md` and the C# SDK README describe the run event stream each SDK already reads (UT-026).
  - An already used verification or reset link answers 400 `LinkUsed` (expired: `LinkExpired`; unknown: `LinkInvalid`), and a used verification link tells the reader to sign in (UT-027).
  - The MCP server in stdio mode writes protocol messages to standard error only with `--verbose`, and a signal that arrives after the run has ended no longer crashes it with `ObjectDisposedException` (UT-028).
  - Unmatched `/v1.0/public/...` and `/.well-known/...` paths answer 404 `RouteNotFound` instead of 401, and a database that cannot be reached answers 503 `DatabaseUnavailable` with `Retry-After` instead of 500 (UT-029).
  - The run email subject and lead count the findings the email shows, and an email that shows fewer than the run found says "This email shows the top N of M new findings" (UT-030).
  - `benchmarks/README.md` lists every stub URL and how to configure a server with it, and the stub command takes `--stub-bind` and `--stub-host` so a Docker stack can use it (`--stub-bind '*' --stub-host host.docker.internal`) (UT-031).
  - Responses no longer carry Watson's request-style default headers (`Host` with the internal bind address, `Accept`, `Accept-Language`, `Accept-Charset`) (UT-032).
  - `GET /v1.0/api/server-info` returns the operating system, .NET, database, schema, pending restart, and bundled tool details only to global administrators; members get the product, version, and uptime (UT-033).

- Settings: an unchanged round trip no longer reports list settings as changed, and list settings are described as `list` (the dashboard edits them as comma-separated values).
- MCP servers: the unsupported SSE transport is refused instead of silently using Streamable HTTP; topics refuse tool IDs that are not tools in the tenant; deleting a server removes its tools from topics' allow-lists; a server that stops responding mid-call reports a connection failure (502) instead of 500; tool lookups honor cancellation.

- Found by the benchmark suite: search requests were never retried, so a single 429 (or 502, 503, 504) from SearXNG failed the query, and a run whose queries all hit one failed. Search now retries 408, 429, and 5xx responses up to `search.maxAttempts` (default 3), waiting for `Retry-After` (at most 5 seconds) or an exponential backoff.
- Found by the benchmark suite: pages fetched by a run that then failed, or by a dry run, were remembered as seen, so the next run skipped them and their findings were lost (after a model outage the recovery run showed 1 finding where a healthy run shows 11). A page now counts as seen only when a finished, non-dry run fetched it.
- `REST_API.md` and the Postman collection list the `CapReached` email template.
- OpenAPI declares the `userId` and `mine` filters on every list route that reads them, the request history summary and bulk delete filters, and the feedback page's `a` value; the bulk delete no longer advertises paging, and `GET /v1.0/api/usage/me` no longer lists values it ignores.

- The MCP server bound its Prometheus endpoint to `*`, which Radiant rejects, so setting `MYMORNINGNEWS_MCP_PROMETHEUS_PORT` turned all MCP telemetry off. It now binds `MYMORNINGNEWS_MCP_PROMETHEUS_HOSTNAME` (default `127.0.0.1`, `mcp` in compose).
- Deleting a user removed their topic rows through a database cascade but left the topics' runs, findings, briefings, and editions behind. User deletion now removes everything the user owns first (`AccountDataService`), which Phase 14 account deletion will reuse.
- Credential auth modes are enforced: `SignedRequest` credentials refuse `x-secret-key` and session exchange, and `SessionExchange` credentials work only through `POST /v1.0/token`.
- Abandoning a refinement of an existing Draft topic no longer deletes that topic.
- Saving a briefing template keeps the name given at creation unless the front matter name changes.
- Credential updates and deletions are audited under their own event and mutation names.
- A member could read another member's fetched source by ID; sources are now visible only to members whose topics found them.
- Deleting a topic now also removes its feedback, reason tags, learned preferences, learning checkpoints, email action tokens and suppressions, prompt overrides, and model assignments. Sent emails stay in the outbox with the topic cleared.
- Feedback ratings are checked against the item type even without an action, and an action on a learned preference gets a clear message.
- Validation messages no longer end with the parameter name. Empty source and template lists report zero pages and their duration. The prompts tenantOnly filter is applied before paging, so counts are right. OpenAPI: the model test body is declared and `search` is no longer listed twice.
- `/openapi.json` sent `Access-Control-Allow-Origin` twice, which browsers reject.

Each briefing is stored as Markdown and a self-contained HTML report for up to 365 days, or longer when pinned, on local disk or S3.
- Audio: every edition (and any briefing you ask for) can become an episode with chapters, spoken by the bundled Kokoro voices or any OpenAI-compatible speech service, with a private podcast feed you can subscribe to in any podcast app.
- Email: a digest after every run and an email for each edition, with links to every item and one-tap feedback (Relevant, Not relevant, Tell us why) that opens a short form, plus one-click unsubscribe per topic. Works out of the box by writing emails to files; set Mailgun keys to send for real.
- Learning: your ratings and reasons shape what the next run ranks highly and what it searches for, recurring reasons turn into preferences you can apply with one click, and Insights reports show relevance, prediction accuracy and calibration, feedback, suggestions, and evidence quality.
- Promotional codes: administrators can create codes that give a free subscription for a set number of days, cap how many people can use each one, generate batches, see who used them, and revoke them.
- `OWNER_ACTIONS.md` with everything the owner needs to do, grouped by phase.
- Analytics overview (`GET /v1.0/api/analytics/overview`): active topics, runs by outcome, findings shown and rated, relevance precision, briefings, emails, predictions and accuracy, feedback, suggestions, quote failure rate, and model calls and cost in one call.
- Email analytics (`GET /v1.0/api/analytics/email`): sent, failed, pending, and skipped counts, delivery rate, mean time to send, breakdowns by template, day, and status, feedback link use, and unsubscribes. The feedback report adds a split by day and channel.
- Findings can be pinned and hidden (`PUT /v1.0/api/findings/{id}`) and deleted; hidden findings stay out of lists, briefings, and emails. `GET /v1.0/api/evidence/{id}` and `GET /v1.0/api/runs/{id}/llm-calls`.
- SDKs for C# (`sdk/csharp`, NuGet-ready `MyMorningNews.Sdk` for net8 and net10), JavaScript (`sdk/js`, ES module with type declarations), and Python (`sdk/python`), each with signed-request support and a harness that runs against a live server.
- MCP server (`src/MyMorningNews.McpServer`, Voltaic): Streamable HTTP on `/mcp` (port 12105, compose profile `mcp`) and stdio, 26 tools, four Markdown resources, and two prompts, acting with the caller's own credentials.
- Agentic search (opt-in per topic): tool-capable research models search and read with `web_search`, `fetch_url`, and allowed MCP tools, capped by `Pipeline.MaxToolCallsPerRun` and logged per call (`GET /v1.0/api/runs/{id}/tool-calls`); the picked pages still go through quote verification.
- MCP server registry (`/v1.0/api/mcp-servers`): register remote Streamable HTTP servers with a vault credential, test, discover tools, and choose which tools research may use.
- Plans: Free is $3 a month, 1 topic, daily schedules, and 10 audio minutes; Complimentary (from promotional codes) is $10, 2 topics, daily, and 30 audio minutes. Existing installs move off the earlier defaults unless an administrator changed them.
- SDK publishing workflow for NuGet, npm, and PyPI (runs only when the registry secrets exist) and the MCP registry `server.json`.
- Mobile bundle identifier is `ai.latticetech.mymorningnews`.
- The retention worker also prunes expired refresh tokens and email action tokens, and audit records when `Diagnostics.AuditRetentionDays` is set (0, the default, keeps them).
- Run progress as server-sent events (`GET /v1.0/api/runs/{id}/events`) and retry from a stage (`POST /v1.0/api/runs/{id}/retry?fromStage=`), in the API and all three SDKs.
- The server image includes Node.js 22 with npm, Claude Code, Codex, Gemini CLI, git, ripgrep, and Mux (versions set by build arguments). Ollama remains available in compose with `--profile ollama`.
- Client config reports the MCP endpoint (`Rest.McpPublicUrl`), and a credential's auth mode can be changed after creation.
- Dashboard: a live stage timeline for running runs, retry from a stage, and a Sources page with full text. Also pin, hide, and delete findings; evidence in context; a run's model calls; Insights overview and email delivery pages; credential auth modes; an MCP client page. Mobile: pin, hide, and delete findings, and an overview on Insights and Today.
- Signed requests (`MMN1-HMAC-SHA256`): machine clients sign each request with the credential secret instead of sending it, with a clock skew window (`Auth.SignatureMaxSkewSeconds`, default 300) and nonce replay protection.
- Scope guardrail on every model call and in every default prompt, so models stay on research and briefing tasks and treat fetched content as data.
- Prompt templates: 19 defaults, renderer with list expansion, save-time variable validation, versions, rollback, reset, topic overrides, and a prompt lab.
- New tenants are seeded with an Anthropic `claude-opus-5-5` endpoint, an Ollama `all-minilm` embedding endpoint, assignments for every task, and the default prompts.
