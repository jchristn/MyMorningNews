# My Morning News mobile app

The My Morning News app for iPhone, iPad, and Android phones and tablets (plan section 35). Read the latest
briefing, listen to it with the screen locked, manage topics, see how the research is working, and manage your
account, against the hosted service or a server you run yourself.

Expo SDK 58 with React Native 0.88, React 19.3, expo-router, and JavaScript with JSX (like the dashboard). Version
`0.1.0-alpha` (store version `0.1.0`, build 1). (c) 2026 Lattice AI LLC.

## Running it

```bash
cd mobile
npm ci
npm start                 # Metro on port 12191; press i for the iOS simulator, a for Android
npm run run:ios           # build and install a development build on the iOS simulator (expo run:ios)
npm run run:android       # same for an Android emulator or device
npm run verify            # lint, i18n check, parity check, audit check, Jest, expo export for iOS and Android
```

The app talks to `https://app.mymorningnews.ai` by default. For local development, tap **Change server** on the
sign-in screen: the iOS simulator reaches the Docker stack at `http://127.0.0.1:12100`, the Android emulator at
`http://10.0.2.2:12100`, and a phone at `http://<your computer's LAN address>:12100`. Plain HTTP shows a warning.
The local default sign-in is `admin@mymorningnews` / `password` (tenant `default`, which the server finds on its own).

`ios/` and `android/` are generated by `expo prebuild` (Continuous Native Generation) and git-ignored, as in
MuxCloud and TrellisKit. All native configuration lives in `app.config.js` and config plugins. Physical devices,
emulators, and free personal-team signing are in [docs/MOBILE_DEVICE_TESTING.md](../docs/MOBILE_DEVICE_TESTING.md).

## How it connects

| What | How |
| --- | --- |
| Sign in | `POST /v1.0/token` with `x-email`, `x-password`, `x-client: mobile`, and no tenant: the server finds it from the credentials. A `409 TenantSelectionRequired` lists the workspaces; the app asks which one and repeats the sign-in with `x-tenant-guid` (contract B), and a list of one is used without asking. The screen has no tenant field, so an older server that answers `400 x-tenant-guid is required` gets its message shown as it is. A `403 EmailNotVerified` (a sign-up not confirmed yet) offers "Send a new link". |
| Tokens | The session token and the rotating refresh token (contract A, 30 days) live in the Keychain / Keystore (`expo-secure-store`, `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`), one entry per server. `src/auth/AuthController.js` refreshes 60 seconds before expiry and after a 401 with `POST /v1.0/token/refresh-token`, with exactly one refresh in flight (a reused refresh token revokes the sign-in). Servers without contract A get the authenticated `POST /v1.0/token/refresh`. A rejected refresh shows "Your session expired". Sign out sends `DELETE /v1.0/token`, which also revokes the refresh token. |
| API | `src/api/`: `ApiClient` with an injected base URL, token provider, refresh function, and fetch; typed errors (`ApiError`, `NetworkError`, `TimeoutError`, `SessionExpiredError`, `TenantSelectionRequiredError`); every route in `routes.js`. A 404 (or 405, 501) is "not available on this server yet", and screens say "This arrives in a later server update" instead of showing an error. |
| Client config | `GET /v1.0/api/client-config` (contract D, no auth): server version, sign-up (`signupEnabled`, `requireEmailVerification`, `minimumAge`, `turnstileSiteKey`), push, audio, and email switches, minimum app version, legal links, copyright. Defaults apply when it is missing, and sign-up then stays hidden. |
| Sign-up and recovery | `POST /v1.0/public/signup` (sign-in > Create account, shown only when `signupEnabled`), `POST /v1.0/public/verify-email` and `/verify-email/resend`, `POST /v1.0/public/password/forgot` and `/password/reset`, all without auth. Sign-up always ends on "Check your email" (the server answers 202 the same way whether or not the email has an account), or "Your account is ready" when verification is off; 404 `SignupClosed` shows the closed state. The emailed `/verify?token=` and `/reset-password?token=` links open the app's own screens, which work signed in or out. |
| Profile and usage | `GET/PUT /v1.0/api/me`, `PUT /v1.0/api/me/password`, `GET /v1.0/api/usage/me` (cost, calls, tokens, by task or model, drawn with react-native-svg). |
| Push | `POST /v1.0/api/devices` with the Expo push token, platform, name, and locale (contract C); `GET` lists devices, `DELETE /devices/{id}` removes one (also on sign-out), `POST /devices/{id}/test` sends a test. The permission prompt appears only from Account > Notifications. Taps route by `{ kind, briefingId \| topicId \| predictionId }`. Android channels: `briefings`, `predictions`, `account`. |
| Links | `mymorningnews://briefings/{id}` and `https://app.mymorningnews.ai/briefings/{id}` (also `/dashboard/...`, topics, predictions, findings, suggestions, insights, account, `mymorningnews://redeem?code=...` for promotional codes, and the account emails' `/verify?token=` and `/reset-password?token=`, plus `/signup?code=` and `/login`) map to screens in `src/lib/deepLinks.js`, applied by `src/app/+native-intent.js`. iOS associated domain `applinks:app.mymorningnews.ai`; Android `autoVerify` intent filters. |
| Research (Phases 4 to 7) | Topics with dimensions and constraints, the refinement wizard, one-time requests, schedules (with `POST /v1.0/api/schedules/preview`), runs with stages, queries, and results, findings with evidence (pin, hide, and delete with `PUT` and `DELETE /v1.0/api/findings/{id}`, and the `pinned` and `includeHidden` list filters), sources, predictions with reviews, suggestions, briefings (read, pin, regenerate, download `.md` and `.html`), and editions (edit, topics, compose, preview): `src/api/research.js`. Model-backed steps (wizard generation, request planning) answer `502 ModelError` without a model key; screens say so and offer the manual path (`ActionError` in `src/components/states.jsx`). |
| Audio (Phase 8) | The briefing detail carries `audio` (the newest episode in any status) and the briefing names its ready episode in `mediaAssetId`. `GET /v1.0/api/media/{id}` gives the chapters and `audioPath`; audio streams from `GET /v1.0/api/artifacts/{id}/content` with the bearer token and HTTP Range. `POST /v1.0/api/briefings/{id}/audio` makes audio (409 `AudioInProgress`, `AudioDisabled`, `BriefingNotReady`); the reader polls while it is made. Listen lists `GET /v1.0/api/media?status=Ready`. Make actions and podcast feeds are hidden when client config has `audioEnabled: false`. |
| Podcast feeds | `GET/POST/DELETE /v1.0/api/feed-tokens` (Account > Podcast feeds): the feed URL is shown once with Copy (`expo-clipboard`), Share, and Open in Podcasts (`podcast://` on iOS, `pcast://` on Android). |
| Feedback (Phases 9 and 10) | `POST /v1.0/api/feedback` with `{ targetType, targetId, action, reason, channel: "Mobile" }` from inline chips on findings, predictions, suggestions, briefings, and the findings a briefing cites; the current rating comes from `GET /v1.0/api/feedback?targetType=&targetId=` (or one read per list); the why sheet adds a reason, changes, or retracts (`DELETE /v1.0/api/feedback/{id}`). `src/lib/feedback.js` holds the actions per target. |
| Minimum app version | `src/components/UpdateGate.jsx` compares the installed store version (`0.1.0`, from the app config) with client config's `minimumAppVersion` at launch and each time the app returns to the foreground (`src/lib/version.js`, semantic versioning: `0.1.0-alpha` is older than `0.1.0`). An older app gets a full-screen "Update required" message that cannot be dismissed, with a button to the store listing when one is known. A missing or unreadable value never blocks, a failed config read keeps the last verdict, and a block from a self-hosted server offers the hosted service. |
| Offline feedback and connection state | Every feedback write goes through `useFeedbackActions` (`src/state/OfflineContext.jsx`). Without a connection, or after a network failure, the action goes to `src/feedback/FeedbackQueue.js`: kept in AsyncStorage per signed-in identity, at most 100 actions, the last rating per item wins, sent in order when the connection returns, and checked against the server's current rating before a retry so nothing is applied twice. A 4xx answer drops the action with a quiet notice; a failing server is retried five times. The control shows "Will send when online". Signing out clears the queue. `src/net/ConnectivityMonitor.js` follows `expo-network` and every API exchange and probes client config until the server answers; `src/components/ConnectionBanner.jsx` sits above the mini player and the tab bar, says "You are offline" or "Cannot reach the server" with the number of ratings waiting, and clears itself. |
| Insights and learning (Phase 10) | `GET /v1.0/api/analytics/{overview,relevance,accuracy,feedback,suggestions,reasons,quality}` with `from` and `to` (the overview tiles head Insights and Today), drawn with the hand-rolled charts in `src/charts/` (bars, trend line and columns, calibration diagram); feedback history with `PUT` and `DELETE /v1.0/api/feedback/{id}`; learned preferences with accept, reject, disable, enable, edit, delete, and create. |
| Plans, codes, email | `GET /v1.0/api/account/plan` and `POST /v1.0/api/promo-codes/redeem` (409 `PromoCodeInvalid` with `details.reason`, each explained; `src/lib/promo.js`); `GET/PUT /v1.0/api/email-preferences`. |
| Account data | `POST /v1.0/api/account/delete` (Account > Delete account, type DELETE, then sign out) and `GET /v1.0/api/account/export` (a ZIP through the share sheet). Both degrade to "later server update" (and the web deletion page) on a server without them. |

## Audio player

`src/player/` is one `PlayerService` (the Listen tab, the mini player, and the lock screen share it) over
**`expo-audio`**, with a pure state machine (`machine.js`) that the tests drive: play and pause, back 15 and forward
30 seconds, scrubbing (tap, drag, or the accessibility adjust actions), speed 0.75x to 2x with pitch correction,
chapters (marks on the scrubber, previous and next, a chapter list), a sleep timer (minutes, end of chapter, end of
episode), downloads into the app's documents folder with storage management (`downloads.js`), and the resume
position saved locally and synced to `PUT /v1.0/api/briefings/{id}/progress` (`progress.js`; a 404 stops the sync
for the session).

**Why expo-audio and not react-native-track-player.** The plan's spike asked whether `expo-audio` on SDK 58 does
background playback, lock-screen metadata and controls, and the Android media notification. It does:
`setAudioModeAsync({ shouldPlayInBackground: true, interruptionMode: 'doNotMix' })` keeps the session alive in the
background, `player.setActiveForLockScreen(true, metadata, options)` publishes title, artist, album, and artwork to
the iOS Now Playing center and the Android media session, and its options set the skip intervals
(`seekBackwardIntervalSeconds: 15`, `seekForwardIntervalSeconds: 30`), which iOS draws into the glyph and Android
shows as numbered skip icons. The config plugin adds `UIBackgroundModes: audio` and the Android
`AudioControlsService` foreground service with `FOREGROUND_SERVICE_MEDIA_PLAYBACK` (Android stops background audio
after about three minutes without it). Staying on `expo-audio` keeps the app inside the Expo SDK with no extra native
module to keep in step. The spike results are recorded in "Verification" below.

The briefing reader makes, plays, and downloads a briefing's audio, lists its chapters (tap to play from one), and
marks the section being read aloud (a chapter names its briefing section, or matches a heading by title). A download
keeps the episode ID and chapters beside the file, so it plays offline from Listen > Downloads, and a remade episode is
not mistaken for the downloaded one. Development builds also have a hidden **Developer
player** (Listen > Developer player) that plays a bundled four-minute test tone (`assets/audio/test-tone.m4a`, four
one-minute chapters, a beep every ten seconds; regenerate with `npm run assets:tone`). The tone is resolved to an
empty module in release bundles (`metro.config.js`), so it never ships.

## Layout

Signed out: sign-in (with Create account when sign-up is open, and Forgot password?), server, sign-up, forgot
password, and the verify email and reset password screens that emailed links open.

**Turnstile.** The app has no WebView (briefings render natively, so nothing in the app runs web content), and
Cloudflare Turnstile has no native widget. When client config carries a `turnstileSiteKey`, the sign-up screen
explains that the server asks for a check the app cannot show and opens the web sign-up page (`<server>/signup`, the
same origin on the hosted service) in the in-app browser, then the person comes back and signs in. Adding
`react-native-webview` only for this was not worth a native module.

Phones use five tabs (Today, Listen, Topics, Insights, Account), each a stack. Tablets and windows 768 points and
wider show split views (the briefing, finding, prediction, request, topic, and edition lists beside their detail, and
the Account menu beside the chosen section) and keep the mini player as a persistent bar above the tabs.

- **Listen:** ready episodes (tap to play, or open the briefing), the full player, downloads that play offline, and a
  link to the podcast feeds.
- **Insights:** the overview tiles (runs, findings shown and rated, relevance precision, prediction accuracy, and feedback) for 30, 90, or 365 days, then Relevance (tiles, precision over time, by topic, tier, dimension, and source, and evidence quality),
  Accuracy (tiles and the calibration diagram), Feedback (volume, channels including MCP clients, themes, suggestion outcomes, and the history
  with edit and retract), Learned preferences, and Your usage.
- **Account:** profile, password, Plan and codes (with Redeem), usage, notifications, Email preferences, Podcast feeds,
  language, appearance, app lock, server, about, export, and delete.
- **Today:** the latest ready edition briefing, Compose now with status polling, recent topic run briefings, At a glance
  (the overview tiles for the last 30 days, hidden on a server without the overview), one-time
  requests (list, new, detail with questions, confirm, cancel, make recurring), and links to briefings, findings,
  predictions, and suggestions.
- **Briefing reader:** Markdown parsed by `src/lib/markdown.js` into native Text and View elements (no WebView and no
  HTML, so briefing content cannot run anything; links open only for http, https, and mailto), section navigation,
  citation numbers that jump to the Sources section, the findings and predictions it cites, pin, and share or save the
  `.md` and `.html` files through the share sheet (`src/lib/briefingFiles.js`).
- **Topics:** the list, the compact wizard (Describe, Dimensions, Questions, Brief, Review; `src/lib/wizard.js`), and the
  workspace with Overview, Findings, Runs, Sources, and Schedule tabs; run detail with stages, totals, and a
  hand-rolled SVG stage chart; editions with settings, topics in order, schedule, Compose now, and Preview. Light and dark themes follow
the system unless chosen under Account > Appearance; the tokens mirror the dashboard's palette (`src/theme/palette.js`).

Accessibility: every control has a label, text scales with Dynamic Type and the Android font size (up to 2x), touch
targets are at least 44 points, reduced motion is respected (`useReducedMotion`), and the bar charts expose their
values as one accessibility label. Arabic and the RTL pseudo-locale mirror the layout on the next launch (Account >
Language offers "Restart now").

## Shared code with the dashboard

Plan section 35.2 has the app import the dashboard's host-agnostic modules instead of copying them, as MuxCloud does.
`sharing.config.js` points `@dashboard/*` at `../dashboard/src/shared`, and Metro (`metro.config.js`), Jest
(`jest.config.js`, `jest.resolver.js`), and ESLint (`eslint.dashboard-shared.config.js`, `npm run lint:shared`) already
resolve and check it. The list of shared directories is empty for now: the dashboard refactor that moves its API
client (with injected storage, base URL, and `onUnauthorized`), i18n catalog, and formatters into `dashboard/src/shared/`
has not landed, so the app keeps its own client in `src/api/` and its strings in `src/i18n/`. Moving a module is:
add its directory to `sharedDirs`, import it as `@dashboard/<dir>`, and delete the app's copy.

## Strings and languages

The app's strings are under `mobile.*` in `src/i18n/catalog/` with ICU syntax, like the dashboard. English is
the source; `es`, `pt`, `fr`, `it`, `de`, `zh`, `ar`, `ru`, `ms`, `hi`, and `ja` translate every key (machine-translated
and awaiting native review; the account screens reuse the dashboard's wording); `qps-ploc` and `qps-rtl` are generated
from English.
`npm run i18n:check` fails on a key the code uses that English lacks, an English key nothing uses, a locale key
English lacks, a changed placeholder, an invalid ICU message, or an em-dash.

## Parity

`parity.json` maps every dashboard route of plan section 25.4 (and the account routes of 33.1) to a screen:
`implemented`, `planned` with the phase that delivers it (and the scaffold screen when one exists), or
`not-applicable` with a reason (operator and administrator pages stay on the web). `npm run parity:check` fails on an
unknown status, a missing screen file, a planned entry without a phase, a reason that is missing, or a plan route the
manifest does not cover. `npm run parity:strict`, used before store submission, also fails on anything planned.

## Backend requirements

Contracts A to D (mobile refresh tokens, tenant-less sign-in, devices, client config) are live. Everything else the
app calls arrives with its plan phase; see `parity.json` for the route list. Gaps found while building the app:

| Need | Why |
| --- | --- |
| `PUT /v1.0/api/briefings/{id}/progress` and `GET` of the saved position | Resume across devices (section 35.5). The app already sends `{ positionSeconds, completed }`. |
| `/.well-known/apple-app-site-association` and `/.well-known/assetlinks.json` on `app.mymorningnews.ai` | Universal links (section 33.3) need the Apple team id and the Android signing certificate fingerprint. The server's file lists `/briefings/*`, `/topics/*`, `/predictions/*`, `/findings/*`, and `/redeem*`; it also needs `/verify*` and `/reset-password*` so the account emails open the app on iOS (Android's intent filters already list them). |
| The web app URL in client config (for example `appUrl`) | With Turnstile on, the app opens `<server>/signup`. That is right on the hosted service (one origin), but a self-hosted server whose dashboard is on another port needs the web address. |
| A distinct error code for unknown routes (for example `RouteNotFound`) | The app tells "not on this server yet" from "this item does not exist" by whether a 404 carries a `requestId` (the server's default handler omits it). An explicit code would make that robust. |
| Store links in client config (`links.appStore`, `links.playStore`) | The update-required screen opens the store listing. Android falls back to the Play listing of the application ID; iOS needs the numeric App Store ID, so without `links.appStore` the screen shows the message with no button. |
| An idempotency key on `POST /v1.0/api/feedback` | The offline queue avoids sending a rating twice by reading the current rating before it retries. A key the server honors would make that exact, and would keep a second history row from appearing in the rare case the check itself cannot run. |
| A `GET /v1.0/api/suggestions/{id}` | The briefing detail now carries `itemTitles` (the app uses it, and reads findings and predictions one by one only on older servers), but a cited suggestion still opens the suggestions list, since there is no read route. |
| A "mine" filter on editions, briefings, and topics for administrators | Administrators list every user's editions; Today keeps the signed-in user's own by `userId` on the client. |
| The request ID on a failed `POST /v1.0/api/requests` | Planning failures (502 ModelError) still save the request, but the error does not name it; the app finds it by listing the newest request with the same text. |
| `editionName` and `topicName` on briefing list items, and a schedule summary on topics | Lists show the date and kind only; the dashboard columns (edition, schedule) need an extra read per row. |
| Feed URLs after creation | `GET /v1.0/api/feed-tokens` returns no URL (only a hash is kept), so a feed whose link was not copied must be revoked and created again. |
| `planName` on upcoming plan periods | `GET /v1.0/api/account/plan` lists `upcoming` assignments with a `planId` only; the app shows the source and dates. |
| Target titles on feedback items | The history shows the rating, reason, channel, and date, and opens the target, but cannot show the item's title without one read per row. |
| `GET /v1.0/api/analytics/overview` | The dashboard Home panels (parity `/home`) need it; Today shows briefings only. |
| Per-topic run email resubscribe | `email-preferences` reports `unsubscribedTopicIds` but `PUT` cannot turn one back on; the app only counts them. |

## Builds, updates, and stores

`eas.json` has `development` (simulator build and APK), `development-device`, `preview` (TestFlight and Play internal
testing), and `production` profiles, each on its own update channel, plus `submit` placeholders. Nothing builds or
submits automatically.

Over-the-air updates use `expo-updates` with EAS Update and **mandatory code signing**, after TrellisKit:
`updates/certificate.pem` is the public certificate, `npm run updates-certificate` creates it (the private key goes
to `~/.mymorningnews/keys/updates/`, never into Git), and `npm run publish-update -- --channel <c> --message "..."`
publishes a signed update (dry run without `--publish`). The runtime version follows the native fingerprint, so an
update only reaches binaries with the same native code. Key rotation needs a new binary; see `updates/README.md`.
Until the certificate and the EAS project exist, builds print a warning and ship with updates off.

Store metadata, privacy answers, age rating, screenshots, review notes, and the build and submit steps are in
[`APP_STORE_SUBMISSION.md`](../APP_STORE_SUBMISSION.md) at the repository root. What only the owner can do is in
[`OWNER_ACTIONS.md`](OWNER_ACTIONS.md).

| Variable | Used for | When empty |
| --- | --- | --- |
| `MYMORNINGNEWS_MOBILE_EAS_PROJECT_ID` | `extra.eas.projectId` (push tokens) and the EAS Update URL | No push tokens, updates off |
| `MYMORNINGNEWS_MOBILE_BUNDLE_ID` | iOS bundle id and Android package | `ai.latticetech.mymorningnews` |
| `MYMORNINGNEWS_MOBILE_EAS_OWNER` | Expo account | `joel-christner` |
| `MYMORNINGNEWS_MOBILE_LOCAL_TEAM_ID` | Free personal Apple team for device testing (bundle id `<id>.dev`, no push or associated domains) | Normal signing |
| `GOOGLE_SERVICES_JSON` | Firebase config for Android push (EAS file variable; local `./google-services.json` is git-ignored) | Android builds work without push |
| `MYMORNINGNEWS_MOBILE_UPDATES_DISABLED` | `1` builds without over-the-air updates | Updates on when the certificate and project exist |

## Verification

Automated: `npm run verify` (lint, i18n, parity, audit, Jest, export). Against a running server,
`MYMORNINGNEWS_LIVE_SERVER=http://127.0.0.1:12100 npx jest src/__tests__/live.test.js` checks contracts A to D end to
end (tenant-less mobile sign-in, refresh-token rotation and reuse revocation, devices, client config). On simulators and
emulators, the Maestro flows in `e2e/` drive sign-in, every tab, the Account sections, the theme, the RTL
pseudo-locale, the tablet split view, and the developer player (see `docs/MOBILE_DEVICE_TESTING.md`).

Player spike results (iOS simulator, expo-audio 58): the Now Playing center received title, artist, album, artwork,
duration, elapsed time, and rate; the remote command center registered play, pause, toggle, seek, skip backward with
a preferred interval of 15, and skip forward with 30 (next and previous track disabled); and the test tone kept
playing with the app in the background (position advanced from 1:01 to 3:55 at 1.5x, sleep timer still counting).
The Android media notification and the three-minute background limit need a check on a device or emulator with the
notification shade open (`docs/MOBILE_DEVICE_TESTING.md`, "What to check").
